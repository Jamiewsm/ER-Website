# 장학 후원 안내와 수동 송금 확인

Track: site. 공개 페이지는 `/#support`, 문의는 `/#apply?track=support`이다. 별도 PG, 구독 결제 서비스, 기부자 계정, 신규 DB를 도입하지 않는다.

## 현재 제공하는 흐름

- 빨간 하트 메뉴 → 장학 간증과 목적 → 한국 계좌이체 / 미국 Zelle 선택.
- 원화는 정수, USD는 소수점 두 자리까지 입력한다. 선택한 금액은 화면 안내용이다.
- 한 번 후원 또는 매월 참여를 선택한다. 매월 참여는 은행 앱에서 직접 예약·변경·해지하며 웹사이트가 자동 출금하지 않는다. Zelle 예약 송금은 은행별로 다르다.
- 입금처 복사 → 은행 앱에서 수취인 확인·송금 → 선택적으로 입금 확인 요청.
- 요청은 담당자 확인 전까지 미확인 상태다. 완료 화면과 접수 메일은 기부금영수증이나 입금 확인서가 아니다.

## 실제 접수를 여는 설정

`js/config.js`의 `window.ER_SCHOLARSHIP_SUPPORT`를 사용한다. 초기에는 온라인 접수와 송금 안내가 모두 닫혀 있으며 이메일 문의 링크가 표시된다. 빈 값을 수강료 계좌에서 자동 추정하지 않는다.

| 설정 | 활성화 전에 확인할 내용 |
| --- | --- |
| `inquiriesEnabled` | 후원 전용 접수 메일을 포함한 `submit-application`이 배포되고 운영 메일 수신이 검증됨 |
| `recipientName` | 실제 수령 주체의 공개 명칭 |
| `receiptNotice` | 영수증 발급 여부와 세액공제에 관한 확인된 안내 문구 |
| `bank.confirmed/name/number/holder` | 후원 수령에 사용하기로 확인된 은행·계좌·예금주 |
| `zelle.confirmed/address/holder` | 확인된 등록 이메일/전화번호와 은행 화면에 표시되는 수취인 |
| `acceptingContributions` | 수령 주체와 모집 방식, 관련 신고·회계 처리 및 영수증 안내 확인 후 접수 개시 결정 |

각 지역은 그 지역 정보가 모두 확인되어야 열리므로 한 지역만 먼저 열 수 있다. 온라인 문의는 송금 안내와 별도로 활성화할 수 있다. 설정 파일에는 공개 입금처만 두며 인증정보나 후원자 정보는 넣지 않는다.

## 접수와 운영 확인

기존 Turnstile과 `submit-application`을 재사용한다. 두 source는 `support:scholarship`(문의), `support:scholarship-transfer`(송금 확인 요청)다. `category`에는 후원 문의/확인 요청을 쓰고 과정명이 들어간 `program_key`를 전송하지 않는다. 서버는 `program_key=general`, `status=received`, `cohort_key=null`로 저장한다.

송금 방법·통화·금액·날짜·문의 내용·동의 표시는 기존 `message`에 포함된다. 운영자 알림 이메일에서 전체 내용을 볼 수 있고, Supabase의 `program_applications`에서 source로 조회할 수 있다. 기존 10월 기본과정 관리자 목록은 과정별 목록이므로 후원 문의를 표시하지 않는다. 이 작업은 별도 후원 대시보드를 만들지 않는다.

운영자는 은행 내역과 이름·날짜·금액을 대조한 뒤 개별 안내한다. 문의자의 입력이나 접수 메일을 입금 근거로 삼지 않는다. 재신청이나 재전송에 대비해 동일한 실제 거래를 중복 집계하지 않는다. 송금 확인 요청은 선택 사항이므로 은행 내역이 대사의 기준이다. 확인된 수입, 장학 적용 금액, 잔액은 통화별 운영 장부로 관리한다. 수강료 감면과 실제 현금 지급은 구분해서 기록한다.

공개 집계는 개인이나 기수를 식별하지 않는 누계만 사용한다. 후원자가 입력하는 정보의 보관·정리와 관련 안내도 접수 개시 전에 운영 절차에 맞게 확인한다.

## 선행 서버 변경

별도 `supabase` track의 `codex/scholarship-receipt`에서 후원 전용 접수 메일을 추가한다. 기존 일반 접수 메일의 수강 등록·결제 약속을 후원 요청에 보내지 않기 위한 변경이다. 서버가 확인되기 전에는 `inquiriesEnabled=false`를 유지한다.

Supabase-only PR은 사이트 자동 배포와 별개다. merge만으로 서버 배포 완료를 판단하지 않고 해당 함수의 실제 배포를 확인한다. 사이트 merge·배포는 저장소의 기존 조율 절차를 따른다.

- `node --test tests/*.test.mjs`: 기존 사이트·교육 기능 회귀 검사.
- 브라우저: 데스크톱/모바일, 준비 상태, 가상 입금처, 한국·미국 전환, 수동 정기이체 안내, 실패 후 재시도. 결제·이메일 전송은 가상 응답으로 격리한다.

현재 정적 사이트의 hash URL 공유는 사이트 공통 미리보기 이미지를 사용한다. 전용 소셜 공유 카드와 후원 장부 자동화는 이 버전에 포함하지 않는다.
