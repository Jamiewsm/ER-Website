# PostgreSQL 검사·배포 원장 복구 계획

Track은 site 배포 제어와 검사 환경이다. 공개 사이트·진단 런타임·운영 DB의 기능 코드는 변경하지 않는다.

1. 누락된 PG_BIN_DIR와 main 직접 push의 GH006을 재현하고 현재 원장 형식을 확인한다.
2. 공식 PostgreSQL 도구를 사용자 로컬에 설치하고, npm test가 도구 경로를 찾아 전체 검사를 실행하도록 한다. 독립 Unix 소켓의 일회용 합성 DB만 사용한다.
3. 원장 생성기를 현재 표 형식·성공한 배포 트랙·실제 source SHA·검증 시각에 맞춘다. 원장 자체는 CI가 생성한다.
4. CI의 main 직접 push와 continue-on-error를 제거하고 별도 브랜치·PR로 저장한다. 브랜치 보호 규칙은 유지한다.
5. 실패→통과 회귀 검사, 전체 검사, CSS/문법 검사와 CI를 확인한 뒤 병합한다.
6. CI site-only 복구 배포에서 원장 PR 생성·병합·원격 파일 보존을 검증하고 실제 운영 파일과 화면을 확인한다.

완료 기준은 전체 검사 실패0/skip0, 원장 원격 main 반영, 운영 site/test 보호 확인이다. 실제 신청·메일 발송·운영 DB 쓰기는 하지 않는다.
