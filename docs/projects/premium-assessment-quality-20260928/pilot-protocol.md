# 문항 비교 파일럿 운영안

이 문서는 실행 가능한 모집·검토 순서를 정의한다. 실제 참가자 모집, 상담 판단 수집, 무작위 배정은 아직 시작하지 않는다. 웹사이트에는 자동 A/B 배정을 넣지 않는다. 현재 구현 버전의 고객 평가를 모으는 것과 별도 파일럿의 비교 결과를 혼합하지 않는다.

## 용어와 측정 대상

- 유형은 장·가슴·머리의 3센터와 9가지 유형을 포함한다. 센터 점수만으로 유형을 확정하지 않는다.
- 하위유형은 자기보존(자본), 성적/일대일(성본), 사회적(사본)의 27가지 유형별 표현이다.
- 날개는 인접한 두 유형의 영향이다. 어느 한쪽을 반드시 확정하지 않는다.
- 체감 일치도, 반복 검사 안정성, 상담 판단과의 일치를 각각 보고한다. 어느 하나도 단독으로 정답률이라 부르지 않는다.

## 1차 연구. 문장 이해 과정 확인

두 차례에 걸쳐 각 10–15명에게 문항을 읽고 무엇을 떠올렸는지 확인하는 것을 운영상 출발안으로 삼는다. 이는 표본 수의 통계적 적정성을 보장하지 않는다. 에니어그램을 처음 접하는 사람과 경험자가 모두 포함되어야 한다.

연구자는 뜻이 모호했는지, 한 문장에 여러 판단이 섞였는지, 직장·부모·리더 역할 때문에 답했는지, 두 선택지 중 한쪽만 좋게 보였는지 기록한다. 참가자의 실제 사례를 결과지의 유형에 맞추어 해석하지 않는다. 연구 목적의 대화이며 공개 검사에는 주관식을 추가하지 않는다.

아래는 검토 형식을 설명하기 위한 새로운 한국어 초안이다. 체스넛 검사지의 번역이나 검증된 문항이 아니며 운영 코드에 적용하지 않았다. 한 문항으로 해당 유형을 판정하지 않는다.

| 초점 | 관찰 장면 초안 | 구별해 확인할 이유 | 다른 설명·검토할 위험 |
|---|---|---|---|
| 1 | 일을 마친 뒤에도 기준에 못 미친 부분이 계속 눈에 들어온다. | 기준을 어긴 불편과 평가·문제 발생 걱정의 차이. | 꼼꼼함, 직무 책임, 3·6번과 중첩. |
| 2 | 가까운 사람이 무엇을 필요로 하는지 먼저 살피다 내 부탁은 뒤로 미루곤 한다. | 관계에서 필요한 사람이 되려는 마음과 긴장을 줄이려는 마음. | 돌봄 역할, 9번, 도움을 받으려는 자기보존 2번 누락. |
| 3 | 맡은 역할에서 성과를 내지 못하면 쉬는 동안에도 그 일이 마음에 남는다. | 유능함을 보여 주려는 마음과 기준·안전에 관한 염려. | 평가 제도·생계 압박, 자기보존 3번의 직접 인정 욕구 부인. |
| 4 | 좋은 일이 있어도 내게 없는 무언가가 더 선명하게 느껴질 때가 있다. | 비교·결핍과 현실적인 어려움의 차이. | 최근 상실, 자기보존 4번의 견디는 표현. |
| 5 | 갑자기 부탁을 받으면 먼저 필요한 시간과 에너지를 가늠하는 편이다. | 자원·경계 보존과 단순한 피로의 차이. | 과도한 업무, 자기보존 관심, 모든 내향성을 5번으로 보기. |
| 6 | 다른 사람은 괜찮다고 해도 빠뜨린 문제가 없는지 확인하고 싶을 때가 많다. | 확실성을 얻으려는 마음과 완성도 기준의 차이. | 안전 책임이 큰 직무, 성본 6번의 먼저 맞서는 표현. |
| 7 | 답답한 일이 생기면 다른 선택지나 다음 계획을 먼저 떠올리는 편이다. | 불편에서 벗어나려는 마음과 현실적인 문제 해결. | 창의적 역할, 사본 7번의 희생·이상 추구 누락. |
| 8 | 내 의지와 상관없이 상황이 정해지면 직접 나서서 바꾸려는 편이다. | 자율·주도권과 공정·안전 문제의 차이. | 권한 있는 역할, 사본 8번의 보호와 연대. |
| 9 | 내 의견을 말하기보다 상황이 부드럽게 지나가게 두는 편이다. | 긴장 완화와 승인·안전·자원 보존의 차이. | 권력 차이, 문화적 예절, 협업 역할. |

문항 검토표에는 ID, 버전, 측정 의도, 책의 관련 절, 혼동 가능 유형, 한국어 해석, 수정 이유를 남긴다. 특정 유형에 쉬운 긍정 단어만 몰리지 않게 한다. 반대유형이라는 이유로 모든 반대 응답을 해당 유형의 근거로 해석하지 않는다.

원문 근거는 Chestnut 2013년 PDF 24–25·32–33쪽의 주의·동기·하위유형 설명, 472–474쪽의 유형 구별 안내다. 반대유형의 구체적 근거는 128–130·179–183·235–237·320–323·366–369쪽이다. 이 쪽수는 사용자 제공 PDF 기준이다.

## 2차 연구. 현재형과 최소 개선형 비교

우선 비교할 질문은 ‘단어와 짧은 문장 중 어떤 표현에서 사람들이 의도한 상황과 의미로 답하는가’다. 연구에 들어갈 전체 문항 세트가 아직 준비·검토되지 않았으므로 9개 초안으로 전체 검사를 대체하지 않는다.

파일럿 시작 전에 다음 값을 정하고 문서에 고정한다. 미정이면 모집·자동 배정을 시작하지 않는다.

| 항목 | 고정할 내용 |
|---|---|
| A/B 버전 | 같은 유형·개념을 다루는 완성된 단어 세트와 문장 세트. 문항 수·순서 정책도 명시. |
| 동일 조건 | 응답 안내, 후보 재검토, 후속 상황 문항, 채점, 결과 내용·디자인. |
| 1차 지표 | 의도와 다르게 이해한 문항의 비율. 판정 기준과 연구자 기록 양식을 먼저 정의. |
| 함께 볼 지표 | 판단 불가, 문항별 시간, 후보 포함률, 결과 보류, 상담 자기보고·독립 상담 비교의 분리. |
| 채택 금지 조건 | 이해도만 좋아지고 후보 포함·응답 부담이 허용 범위보다 나빠진 경우. |
| 수치 기준 | 허용할 저하, 필요한 사례 수, 관찰 기간, 중단·채택 조건을 자료를 보기 전에 결정. |
| 배정 | 동의한 참가자를 배정하고 기록. 두 버전을 모두 수행하면 순서·학습 효과를 통제. |

이전 전체 검사와 새 전체 검사를 비교하면 전체 흐름의 차이를 평가할 수 있으나 단어형만의 효과로 해석할 수 없다. 안내와 결과 디자인을 동시에 바꾸지 않는다.

## 3차 연구. 상담 및 반복 검사 비교

Typing 세션 연구자는 가능하면 검사 결과를 보기 전에 후보·판단 근거·확신 수준을 기록한다. 참가자가 이미 결과를 보았는지도 남긴다. 일부 사례를 두 번째 상담자가 독립 검토한다. 연구자 간 이견은 실제 이견으로 보존한다.

재검사는 같은 버전으로 진행한다. 간격은 연구 계획에서 정하며 중간에 상담·기본과정·관련 학습을 했는지 기록한다. 결과가 달라졌다는 것만으로 첫 검사가 틀렸다고 결론 내리지 않는다.

현재 공개 평가는 참여자 연결정보를 수집하지 않는다. 따라서 공개 평가 내역만으로 재검사·독립 상담 일치를 계산할 수 없다. 이를 위한 별도 동의·연결 절차는 연구 시행 전에 마련한다.

문항·가중치·후보 검토·보류 규칙은 검증 표본을 보기 전에 고정한다. 자료를 보고 수정하면 개발 자료로 취급하고 새 버전은 별도 확인한다. 27개 하위유형 전체를 검증했다고 말하려면 하위유형별 표본과 불확실성도 확인해야 한다.

## 데이터와 분석

기존 실험 테이블 export와 신규 `diagnostic_result_feedback` export는 같은 분석 도구로 읽되 출처·버전별 그룹을 유지한다.

```sh
node scripts/analyze_diagnostic_experiments.mjs --input /path/to/exported-rows.json
```

공개 고객 평가에는 이름·연락처·원응답을 넣지 않는다. 기존 실명 실험은 참여 동의와 명시 제출을 유지한다. CLI에 실자료를 사용할 때 저장소에 커밋하거나 PR 첨부로 올리지 않는다.

자료는 제출자 기준이다. 검사 시작자·중단자 이벤트가 없으므로 전체 완료율은 계산하지 않는다. 같은 시도·revision의 중복을 제외하며, 다른 revision도 독립 참가자 수로 세지 않는다. 3단계 옛 체감 평가를 새 5단계로 임의 변환하지 않는다.

## 연구 방법 참고

문항을 읽은 사람이 이해·회상·판단·선택한 과정을 살피는 방법은 [CDC 인지면접 안내](https://www.cdc.gov/nchs/ccqder/question-evaluation/cognitive-interviewing.html)를 참고한다. 작은 표본에서 문항 문제를 찾는 단계와 정확도를 추정하는 단계는 구분한다.

개념과 점수 해석을 먼저 명시하고 개발·검증 근거를 쌓는 원칙은 [AERA·APA·NCME 검사 표준](https://www.testingstandards.net/uploads/7/6/6/4/76643089/standards_2014edition.pdf)의 4.1–4.2 및 응답 과정 관련 부분을 참고한다. 이러한 절차를 채택했다는 사실만으로 ER 검사 성능이 검증되는 것은 아니다.
