## 구현 결정과 검토

- 평온할 때만을 응답 기준으로 제한하지 않았다. 오래 반복되는 평소 모습과 문항에 주어진 일상적 부담·갈등을 함께 안내한다.
- 단어 81개는 유지한다. 유형을 조기에 제외하는 영향을 줄이기 위해 모두 9개 설명을 확인하고 3–4개를 선택한다. 최초 후보와 재검토 결과는 분리하고 재검토가 최초 결과를 덮어쓰지 않게 한다.
- 공통 관심사와 유형별 하위유형 응답이 모두 선명하면서 충돌할 때 하위유형을 보류한다. 유형을 임의로 바꾸지 않는다. 억압 본능 보조 설명도 충돌·근거 부족 시 보류한다.
- 현재 스트레스는 측정하지 않으므로 null과 measured=false로 표현한다. 3문항 응답 비율을 유형 확률처럼 표시하지 않고 응답 수를 보여준다.
- 공개 피드백은 별도 추가 전용 테이블·Edge Function을 사용한다. 실명 실험 테이블의 범위를 공개 이용자로 넓히지 않는다. 이름·연락처·원응답은 공개 제출에 포함하지 않는다.
- 백엔드는 challenge secret 누락 시 거부하고 권한을 서버 SELECT/INSERT로 제한한다. 같은 시도·회차는 동일 본문 재전송만 인정하며 기존 행을 갱신하지 않는다.
- 평가·안내·문항·채점·결과 버전과 시도·회차를 구분한다. 실험 분석에서 상담 결과 자기보고를 독립 확인 정답으로 부르지 않는다.
- 최초 후보가 빈 배열인 사례는 포함 실패로 계산하고, 자료가 없는 경우와 분리한다. 하위유형 비교에는 확정 사례 일치율과 함께 보류·결측 사례 수도 남긴다.
- 교차 검토에서 실명 게이트 복원, 보조자료의 보류 무시, 통계 분모 누락, PDF 평가 UI 노출을 수정했다. 상세 증거는 verification.md에 기록했다.
- 운영 단계는 Supabase 적용·실제 토큰 확인 → test PR 머지·CI 배포 → 실제 제출 검증 순서다. 이 작업에서는 머지·운영 DB 적용·배포를 수행하지 않는다.
- PR은 [서버 #160](https://github.com/Jamiewsm/ER-Website/pull/160), [검사 #161](https://github.com/Jamiewsm/ER-Website/pull/161)로 분리해 생성·첨부했다. 검사 PR은 서버 적용 선행 조건을 표시한 draft다.
