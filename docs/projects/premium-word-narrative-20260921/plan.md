# 프리미엄 검사 업그레이드

## 목표와 범위
사용자가 제공한 유형별 13개, 총 117개 단어에 예 / 모르겠다 / 아니요로 답한 뒤 상위 3~4개 후보의 내적 동기를 선택형 서사 질문으로 비교한다. 유형별 하위유형·인접 날개 확인과 선택적인 짧은 경험 기록을 연결한다. 검사와 결과지는 기존 ER Restoration Green 시스템을 유지하면서 한 문항씩 집중해서 읽도록 개선한다.

Track: test. 운영 진입점 test.html → js/test.js만 발전시킨다. 과거 renderer/scoring 모듈을 재연결하지 않는다. origin/main에서 독립 worktree를 만들었으며 다른 후원 작업은 보존한다.

## 구현 순서
1. 단어 선별과 후보 라우팅. 유형 정보는 문항에서 숨기고 아홉 유형 단어를 섞어 제시한다. 모르겠다는 미응답 및 아니요와 구분한다. 단어 점수는 후보 선별에만 사용하며 동기 점수에 합산하지 않는다. 경계 동률과 정보 부족은 재확인 질문으로 다룬다.
2. 기존 동기/변별 문항과 유형별 하위유형·날개 질문을 재사용한다. 기존 39문항을 그대로 추가하여 피로를 키우지 않는다. 단어 다음부터 상황·동기 선택에 집중한다. 짧은 서술은 선택 사항이며 점수화하지 않는다.
3. 검사 진행, 이전/다음, 선택 상태, 모바일·키보드·문항별 진행률을 정리한다. 결과는 유형/날개/하위유형 요약, 후보 비교 및 판단 근거, 실제 경험 기록, 기존 상세 해석 순으로 읽을 수 있게 한다.
4. 의미 있는 회귀 테스트, 전체 Node 테스트, 실제 데스크톱/모바일 브라우저 검증과 배포 트랙 검증 후 커밋·PR을 만든다. 병합/배포는 저장소 절차에 따른다.

## 디자인 방향
- 팔레트는 er-base #FBFAF5, er-surface #FFFDF8, er-green #657453, er-greenDark #566647, er-sand #E2D8C8, er-ink #202219. 기존 CSS 토큰으로 사용한다.
- 제목 SUIT, 본문/선택/데이터 Pretendard. 글자가 핵심이며 장식 그림은 추가하지 않는다.
- 좌측 정렬 헤더, 가늘고 분명한 진행 상태, 여백이 있는 큰 단어 한 개와 동등한 세 응답 버튼.
- 결과는 짧은 요약에서 근거와 상세 해석으로 이어지며 점유율을 유형일 확률로 표현하지 않는다.
- 참고 사이트에서 여백과 한 문항 집중 원칙을 참고한다. 세리프와 카피를 그대로 복제하지 않는다.

## 완료 기준
117개 단어의 정확한 보존, 3~4 후보 선택, 동률/모르겠음 처리, 후보별 동기 변별, subtype/wing 및 서술 기록 전달, 안전한 HTML 렌더, 모바일 가독성, 기존 실험 동의·결과 공유·PDF 경로 보존이 검증되어야 한다. 기능 검증은 실제 유형 판별 정확도의 실증 검증과 구분한다.
