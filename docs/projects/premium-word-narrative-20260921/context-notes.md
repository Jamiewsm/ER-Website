## 구현 결정

- 유형별 단어 수가 모두 13개이므로 예의 개수로 후보를 비교한다. 모르겠다는 아니요 및 미응답과 구분한다. 3위와 4위가 가까우면 4개 후보, 경계 동률이 더 넓거나 모두 같은 응답이면 동기 묘사로 3~4개를 재확인한다.
- 세 후보는 6개, 네 후보는 12개의 쌍별 서사 질문을 동일하게 배분한다. 모든 쌍에서 최소 하나의 구별 응답이 있어야 핵심 유형을 좁힌다. 단어 점수는 서사형 점수에 합산하지 않는다.
- 하위유형과 날개는 기존 유형별 행동 문항 각 3개를 재사용한다. 근거 부족/동률에서는 자기보존 또는 순수유형을 기본값으로 만들지 않는다. 하위유형 미확정 결과에는 실제 핵심 유형 자료만 사용한다.
- 선택적인 600자 경험 기록은 상황 질문 마지막 페이지에 둔다. 핵심 유형이 좁혀지지 않은 사용자도 기록하고 결과에서 읽을 수 있다. 자동 채점/외부 AI 분석은 추가하지 않는다.
- 응답·문항 위치·경험 기록은 현재 탭의 버전별 sessionStorage로 복원한다. 실험 모드 재진입은 동의 화면을 먼저 보여 주고 수락 후 검사 단계 및 진행률을 복원한다. 서버 저장은 기존 명시 제출에서만 이루어진다.
- 후보 비교 막대는 모든 후보의 서사 응답 점유율을 사용하며 유형일 확률이 아님을 표시한다. 하위유형·날개 막대의 분모에는 모르겠다 응답도 포함한다.
- 기존 ER 색상과 글꼴을 적용하고 단어/질문은 한 번에 하나씩 표시한다. 결과 상단에 유형·날개·하위유형을 함께 읽을 수 있는 요약을 둔다. 불확실한 하위유형 문구는 별도 요약 칸에 표시하여 큰 제목의 과도한 줄바꿈을 피한다.

- 브라우저에서 117개 응답 → 후보 재확인 → 서사 비교 → 하위유형/날개 → 결과까지 실행했다. 단어 중간/세부 문항 중간 새로고침 복원, 이전 응답 수정, 처음부터 다시하기도 확인했다.
