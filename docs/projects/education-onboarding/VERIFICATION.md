# 등록 안내·수업 전 준비 검증 기록

2026-09-15 기준. 포털 [PR #22](https://github.com/Jamiewsm/CoachPortal-WebApp/pull/22), Supabase [PR #133](https://github.com/Jamiewsm/ER-Website/pull/133).

## 구현된 사용자 흐름

1. 수석코치가 교육포털 운영 관리에서 기수·반을 선택하고 수업 전 준비의 내용·공개 일시·제출 기한을 저장한다. 기본과정은 승인된 강의계획안·선택 도움 질문 초안을 제공하며 다른 과정에 기본과정 내용을 복사하지 않는다.
2. 신청·승인에서 결제 또는 첫 분납 확인을 체크하고 신청 이메일·이름·반을 확정한다. 이 단계는 메일을 보내지 않는다.
3. 수석코치가 요약을 확인하고 **등록 안내 메일 보내기**를 누른다. 공개 준비 자료와 기한이 없거나 취소·발송 이력이 있으면 안전하게 막는다.
4. 학생이 동일한 신청 이메일을 인증하고 로그인하면 배정된 교실에 연결된다. 별도 계정이나 설문 서비스를 만들지 않는다.
5. 홈의 수업 전 준비에서 강의계획안을 읽고 인쇄·PDF로 저장할 수 있다. 보고서는 직접 입력하거나 임시저장 후 비공개 첨부 파일만으로 제출할 수 있다. 준비 과제는 정규 8회차와 주간 수업·출석 목록에 포함되지 않는다.
6. 수석코치는 계정 연결된 학생의 외부 보고서를 접수할 수 있다. 초안 본문을 읽지 않고 제출 상태만 확인하며 접수된 학생에게 미제출 알림을 보내지 않는다.
7. 알림은 운영 활성화 후 D-3/D-1에만 최대 두 번, 환영 메일 및 앞선 알림 이후 최소 24시간 간격으로 발송한다. 제출·외부접수·취소·철회·기수 종료를 직전에 재검사한다.

## 교차 검토에서 보완한 경계

- 기존 수동 반 배정 경로를 거친 학생도 신청 연결을 보완하고, 이전 포털 탭에서 제출했더라도 실제 enrollment로 제출 여부를 다시 찾는다.
- 외부 접수 RPC와 상태 조회는 학생 초안 본문을 노출하지 않는다.
- 파일 조회 대기 중 로그아웃·같은 계정 재로그인이 일어나면 이전 제출 작업을 중단한다. 이전 요청이 새 작업의 잠금이나 메시지를 덮어쓰지 않는다.
- 발송마다 1초 간격을 두고 부분 실패 시 다음 묶음을 처리한 뒤 누적 실패를 보고한다. 전면 실패·네트워크 오류·잘못된 집계에서는 추가 발송을 중단한다.

## 운영 적용 전 남은 확인

코드 검사·PR 상태는 배포 완료 증거가 아니다. 실제 Supabase 마이그레이션과 함수 적용, 실계정 이메일 인증 및 교실 연결, 실수신 메일·공유 피드백, 운영 마감일과 자동 알림 활성화는 이번 작업에서 실행하지 않았다.

백엔드 PR #133의 `EMAIL_OPERATIONS.md` 순서대로 DB → Edge Functions → 포털 #22 → 자료·기한·수동 메일 확인 → 자동 알림 활성화를 진행한다. 자동 발송은 저장소 변수와 반별 설정을 모두 켜야 한다. 불확실 발송 기록은 자동 해제하거나 삭제해 재전송하지 않는다.
