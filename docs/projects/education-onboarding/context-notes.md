# 맥락과 결정

- 사용자 승인. 포털 PR #22에서 등록·포털 준비·제출·미제출 알림을 이어 구현한다. 등록 안내 메일은 수석코치가 결정하고 보내기 버튼을 눌러야 한다.
- 라이브 GitHub 확인. ER-Website #131/#132는 병합되었고 포털 #21은 OPEN이다. 포털은 #21 head 67541e3를 보존해 새 후속 브랜치로 시작한다. #21 병합 후 main 기준으로 PR을 정리한다. 백엔드는 origin/main 02f9399에서 시작한다.
- 별도 계정 서비스나 설문 서비스는 추가하지 않는다. 기존 Supabase 이메일 가입/인증을 사용하며 서버의 auth.users에 저장된 인증 이메일만 자동 연결 근거로 쓴다. 신청 연락처가 정확한 이메일이면 불일치 연결은 허용하지 않는다.
- 입금 확인은 수석코치의 명시적 판단이며 분납 허용 시 첫 납부를 확인할 수 있다. 등록 확정 RPC와 이메일 발송은 별도 행동이다. 결제 금액 자동 감지나 자동 환영 발송은 추가하지 않는다.
- 강의계획안의 원문은 기존 basic-course-welcome.ts에 있는 사용자 제공 내용을 재사용한다. 화면에 게시할 사전 준비는 수석코치가 실제 반에 저장·공개하고 마감일을 지정한다. 확정되지 않은 수업 날짜는 만들지 않는다.
- 과제는 기존 edu_lessons/submissions/storage를 재사용하고 kind=preparation, position0을 정규 1–8회차와 분리한다. 파일 제출은 실제 private Storage 객체가 있는 경우에만 빈 본문을 허용한다. 기존 일반 과제 검증은 유지한다.
- 메일은 요약과 포털 링크만 포함하며 보고서 답변을 담지 않는다. 새 기능의 수동 등록메일 조건을 우회하지 않도록 구형 pre_survey는 새 흐름 안내 오류로 종료한다.
- API/DB 보호와 실제 운영 적용은 별개다. 새 스케줄은 코드와 dry-run 검증을 제공하고 이 작업에서 운영 활성화나 실수신자 발송을 하지 않는다.

- 후속 GitHub 확인. 포털 #21이 main에 병합되어 #22의 기준 브랜치를 main으로 변경했다. 백엔드 후속 PR은 #133이다. #131/#132의 기존 병합 결과를 보존했다.
- 구현 완료. 본문·파일 제출은 기존 private Storage를 재사용하며 전체 검증 결과와 적용 순서는 VERIFICATION.md에 기록했다. 신규 런타임 의존성은 없다.
- 교차 검토. 기존 수동 배정의 신청 연결 누락, 외부 접수의 초안 정보 노출 가능성, 파일 확인 중 세션 변경, 다수 알림의 부분 실패·제공자 속도 제한을 보완했다.
- 검증 한계. SQL은 격리 PGlite, 브라우저는 합성 서버 응답으로 검사했다. 독립 PostgreSQL 세션 경쟁과 운영 실발송은 확인하지 않았다. 운영 설정은 비활성 상태를 유지한다.
