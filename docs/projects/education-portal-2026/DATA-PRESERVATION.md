# ER 자료 보존 및 비용 기준

용량·비용 확인일: 2026-09-08. 공개 안내 보류 지시 반영: 2026-09-09. 이 문서는 권고와 출시 조건이다. 유료 전환, 자동 백업 설정, 운영 DB 변경 또는 복원 완료를 의미하지 않는다.

## 결정 권고

기존 Cloudflare 정적 화면과 Supabase 프로젝트 한 개를 유지한다. 웹사이트·코치·학생 교실 때문에 DB 프로젝트를 따로 늘리지 않는다. 현재 확인한 DB는 약 16.9MB, Storage 파일 메타데이터 합계는 약 15.6MB(41개)다. 월 전송량은 이 조회로 확인하지 않았다. 현재 저장량만으로는 Free의 DB500MB/Storage1GB 한도 이내다.

무료로 개발을 계속할 수 있으나, 실제 보고서와 학생 과제를 운영하는 중요도를 고려하면 통합포털 운영 시작 전 Pro를 권고한다. 단일 Micro 프로젝트와 포함 사용량 기준 월 $25부터이며 부가 기능·추가 프로젝트·초과 사용·세금은 별도일 수 있다. Pro는 매일 DB 백업을 7일 보관한다. 저장량이 아니라 복구 필요성과 운영 책임을 전환 기준으로 삼는다. 요금제 변경은 사용자가 결정한다.

## 반드시 나누어 보존할 대상

1. DB의 기존 코치 보고서·멘티·설문·신청·새 학사 기록 전체, 계정과 역할·접근정책·DB 함수·마이그레이션 이력.
2. Supabase Storage의 실제 파일 원본 전체와 bucket/path 목록, 크기·해시. DB 백업은 파일 메타데이터만 포함하며 삭제된 파일 원본을 복구하지 않는다.
3. 원본 강의안·과제 문서·영상 원본. YouTube나 Drive 링크가 있다는 사실만으로 해당 영상·파일이 백업된 것은 아니다. 링크 목록과 원본 보관 위치도 관리한다.
4. 애플리케이션 코드와 운영 설정. GitHub의 코드 이력만으로 학생 DB나 업로드 파일이 백업되지는 않는다. 비밀키는 코드와 백업 기록 문서에 넣지 않는다.

## 제안하는 최소 보존 정책

- 운영 DB와 파일을 매일 날짜별로 별도 보관하고, DB 변경 전에는 추가 백업한다. 민감한 기록은 암호화하고 접근자를 제한한다.
- 일별30일·월별12개월 보관은 초기 운영안이며, 실제 개인정보 보관 정책에 맞춰 확정한다. 무기한 보관을 자동 적용하지 않는다.
- Supabase와 다른 저장 위치에 최소 한 벌을 둔다. iCloud의 동기화 폴더 한 개만을 유일한 백업으로 삼지 않는다. 삭제가 전파되지 않는 과거 버전이 필요하다.
- 백업 성공 여부는 행 수·파일 수·크기·해시와 실패 로그로 확인한다. 일부 실패를 전체 성공으로 표시하지 않는다.
- 별도 테스트 환경에서 복원하고 학생·멘토·대표 역할로 읽기 권한까지 검증한다. 권한과 파일을 포함한 복원이 확인되어야 백업 완료로 인정한다.
- 최종 백업 이후의 변경은 복구되지 않을 수 있다. 하루 이내 변경 손실도 허용할 수 없다면 더 잦은 백업 또는 별도의 복구 기능과 비용을 검토한다.

## 이번 릴리스의 출시 조건

기존 보고서와 제출 기록을 초기화하거나 일괄 재작성하지 않는다. 새 교실 테이블과 권한을 추가하고 기존 신청 예약 함수·메일 안내를 보완한다. 공개 웹사이트 PR #123은 보류 상태이며, 교육 DB migration도 기존 `public.public_notices`를 변경하지 않는다. 보류된 공지 문구는 자동 적용 대상 밖의 `supabase/manual/education-public-notices.pending.sql`에 전체 주석으로 보존한다. 사용자의 추가 수정 및 별도 공개 지시 전에는 적용하지 않는다. 학생 원문 질문지는 공개 정적 자산에 넣지 않는다. 질문지를 수업으로 명시적으로 등록한 뒤 접근권한을 적용한다.

운영 DB 적용 전 전체 DB와 실제 Storage 파일 백업의 위치·생성시각·완료상태·복원 검증 결과를 기록한다. 아직 이 작업에서 실제 전체 백업/복원을 수행하지 않았으므로 출시에 앞서 완료해야 한다. 백업·복원 검증 후 Cursor CLI가 DB→포털 순서로 적용하며, 사이트 배포는 별도 보류한다. 실패 복구는 기존 데이터 삭제가 아니라 앱 되돌리기 또는 수정 마이그레이션으로 진행한다.
