# 검증 기록 — 2026-09-10 갱신

실제 계정·실제 DB에 합성 테스트 자료를 넣지 않았다. 운영 DB는 용량·정책·가입 트리거를 읽기 전용으로만 확인했다. 전체 DB/파일 백업, 운영 migration 적용, 유료 전환은 아직 수행하지 않았다.

- 웹사이트(이전 로컬 검증 기록, PR #123 공개 배포 보류): 교육 경로·조건·가격·반당 정원·신청 호환·렌더 검사24개 통과. 실제 SPA 전문가 메뉴와 기본과정 페이지를 Chromium 데스크톱/390px 모바일에서 확인했다.
- Backend: 격리 PGlite(Postgres)에서8개의 통합 시나리오 통과. 익명 차단, 반 격리, 초안 비공개, 제출 보존, 담당 멘토/공유 피드백, 공개 전 자료, 파일 읽기/수정 권한, 여러 역할, 정원7명, A/B14명→C추가21명, 기존 예약 호환, head의 학사 원문 삭제 차단. 기존 신청·메일 및 공개 공지 보류 검사9개 통과.
- 포털: 기존·신규 검사93개 통과. Chromium에서 로그인→반 접근→질문 입력→메뉴 이동 중 입력 보존→임시저장→첨부→제출→멘토 내부/공유 피드백→학생 열람→공지 댓글→수석 수업 생성→원문8개 질문지 가져오기→질문 저장을 확인했다. 미배정 계정과 모바일 가로 넘침도 확인했다.
- 원문 자료:8개 문서,28개 답변 칸. 5번 두 판본을 보존,8번 파일 없음. 비어 있지 않은 모든 원문 문단이 안내/질문에 한 번씩 포함되는지 검사했다. 원본 문서 지시사항은 수업 내용으로만 처리했다.

## 검증 한계

PGlite는 실제 Postgres 쿼리와 RLS를 실행하지만, 운영 Supabase의 Auth/Storage 서비스 전체를 대체하지 않는다. 브라우저 테스트의 HTTP 응답은 PostgREST/Storage 동작을 필요한 범위에서 격리 DB에 연결했다. 다중 DB 연결에서의 경쟁, 실제 메일 인증/재설정과 파일 다운로드 서비스, 운영 계정 및 CDN/SW의 배포 갱신은 운영 전 검증이 남아 있다. Edge Function의 Deno 검사는 로컬 Deno가 없어 실행하지 않았다. 외부 메일을 발송하지 않았다.

## 출시 순서

검증된 전체 백업과 복원 → backend 검토·적용 → 포털 검토·적용 → 운영자 실제 계정 확인 → 질문지/명단 입력 및 학생 가능 시간 취합 후 일정 확정. Cursor CLI가 merge·배포를 담당한다. 사이트 PR #123은 사용자 추가 수정 및 별도 공개 지시 전까지 보류하며, DB·포털 적용 순서에 포함하지 않는다. GitHub merge와 운영 배포는 완료된 로컬 테스트와 별개다.


## 추가 확인 — 2026-09-09

- 기존 예약8명 상태에서도 초기 A/B반 생성 migration이 성공하고 예약을 보존한다.
- 이미 배정된 학생과 웹사이트 예약을 한 정원으로 계산한다. 가득 찬 반에서 같은 학생 재배정, 예약→학생 연결, 정원 감소, 직접 확정, 기존 신청 연결 해제, 다른 기수 연결을 검사했다. 정원 계산 내부 함수는 일반 계정에서 직접 호출할 수 없다.
- 실제 Chromium에서 필수 질문을 비운 임시저장은 성공하고 최종 제출은 차단됨을 확인했다. 수업 공개 취소·학생 등록 해제 후에도 내 성찰 보관함에서 질문/답변이 보이며, 멘토 내부 기록은 공개되지 않는다.
- 멘토는 확인된 기존 멘티 카드로 이동한다. 코치 프로필이 없는 교실 멘토에게 보고서 권한이 생기지 않는다. 잘못되거나 접근 불가능한 멘티 링크도 검사했다.
- 배포 묶음은 커밋된 실행 파일만 포함한다. 미커밋 파일·과제 원문·DB 설정·문서를 제외하고, 환경변수를 생략해도 main 검증을 적용하며 기능 브랜치는 명시적 preview로 전달되는지 실제 로컬 테스트 저장소와 가짜 업로드 도구로 검증했다. 운영 배포 도구는 실행하지 않았다.
- 운영 공개 파일 대조와 원 작업폴더 정리 근거는 CoachPortal PR #4의 PRODUCTION-BASELINE.md를 확인한다. 이것은 전체 DB 백업 근거가 아니다.

## 공개 안내 보류 회귀검사 — 2026-09-09

- 교육 migration 두 개를 격리 DB에 적용해도 기존 `public.public_notices`의 제목·요약·본문·표시 형식·과정 기간·수정시각 및 다른 공지 행이 그대로 유지되는지 비교했다.
- 보류 문구는 `supabase/manual/education-public-notices.pending.sql`에 전체 주석으로 보존했다. 자동 migration에 포함되지 않으며, 해당 파일을 격리 DB에서 실행해도 공지가 변경되지 않음을 확인했다. 검토 자료의 존재는 공개 승인이나 적용 완료를 의미하지 않는다.
- 이 보완 이후 `npm test --prefix tests/education` 8개, `node --test tests/basic-course-october-supabase.test.mjs` 9개 통과. 운영 DB·웹사이트는 변경하지 않았다.
- 현재 코치훈련은 2026년 10~12월 3분기로 운영하며 2027년 신규 2기와 구분한다. 실제 기수·명단·시간을 입력하거나 검증했다는 의미는 아니며, 학생 가능 시간 취합 후 일정 확정이 남아 있다.

## 멘토링 기수 전환 보완 — 2026-09-09

- 종료된 여름 설정은 보관 상태로 두고 가을 날짜를 발명하지 않는다. 기간 밖 날짜가 S01/S12로 고정되지 않으며 일정 미정 상태에서 새 보고서·insight·학생 숙제 링크 생성 및 자동 보고서 동기화가 중지된다.
- 과거 S/C/ISO 키를 현재 기수의 날짜로 해석하지 않는다. 알려진 여름 ISO 연결은 고정하고, 미등록 과거 키는 정확히 같은 키로 조회한다. 현재 기수와 독립적으로 과거 본인 보고서를 여러 페이지에서 읽는다.
- 과거 보고서를 명시적으로 선택하면 원래 저장 키로 수정하며, 존재하지 않는 지난 보고서는 새로 만들지 않는다. 기존 양식의 추가 원문 필드도 유지한다. 클라이언트 저장 검증이며 기존 서버 RLS를 대체하거나 변경하지 않는다.
- 집중 회귀검사8개와 전체 기존/신규93개 통과. 합성 가을 기수에서 한국·미국 시각/DST, 잘못된 키 재사용, 기록1001건 조회, 보류 기간의 학생/수석 화면 집계를 검증했다.
- Chromium390px 화면에서 지난 ISO 주차 선택→원문 표시→답변 수정→제출 및 이전 양식 필드 보존·가로 넘침 없음을 확인했다. 이 멘토링 폼 검사는 API 저장을 가짜 함수로 대체했으며 운영 요청은 차단했다. 별도의 교육 교실 Chromium/PGlite 전체 흐름도 다시 통과했다.
- 실제 가을 반의 보고서 달력 활성화·반별 주차 대조 및 실제 Auth/Storage/SW/복구 검증은 여전히 출시 전 조건이다. 기존 학생 숙제 토큰에 저장된 서버 달력은 변경하지 않았다.

## 독립 리뷰 반영 — 2026-09-10

- 같은 기수의 S/ISO 보고서가 함께 있으면 사용자가 고른 정확한 키의 원문을 우선한다. 폼과 보고서 상세의 호환 조회가 다른 원문을 먼저 고르던 문제를 수정했다.
- 활성 합성 기수에서도 명시적인 빈 주차·잘못된 주차로 태스크 생성/삭제/동기화를 하지 않는다. 빈 값을 현재 주차로 대체하던 문제를 수정했다.
- 위 두 재현을 회귀검사에 추가하여 포털 전체93개 통과. 모바일의 원래 주차·이전 양식 필드 보존 검사도 재통과. 운영 보고서 키 분포만 읽기 전용 확인했으며 원문·DB 데이터는 변경하지 않았다.
