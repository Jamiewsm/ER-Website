# 작업 맥락

- 2026-10-05 두 PR을 정상 머지하고 네 개 migration·승인 문서·cron을 운영 적용한 뒤 포털 배포 성공을 확인했다. 전환 직후 기존 회원 27명을 legacy로 보존하고 과거 동의를 생성하지 않았다.
- 사용자가 DB 비밀번호를 직접 재설정하고 로컬 숨김 입력으로 저장했다. 전체 DB 덤프·역할·Storage 암호화 백업과 로컬 교육·인증·Storage 스키마 복원 82개 테이블·3,098행 검증을 마쳤다. 플랫폼 전용 확장 재현과 객체 권한 복원을 구분한다.
- 공개된 신규 가입의 서버 상태는 이메일 인증 완료·active·동의 6건·신청 1건이다. 누가 가입했는지나 실제 메일함 내용은 조사하지 않았다. 실제 학생 승인은 운영자가 처리한다.
- 기존 DB 알림 트리거의 legacy 관리자 토큰을 복원 오류에서 발견했다. 해당 오류 로그를 삭제하고 후속 로그 마스킹을 추가했다. 원본 암호화 백업은 보존하고 토큰 교체는 별도 운영 작업으로 남겼다.

- 사용자가 백업 전 머지·배포 후 백업·검증 순서를 명시적으로 지시했다. 실제 DB 적용은 비파괴 추가 migration으로 진행하고 증거·교육 기록 삭제는 실행하지 않는다. 기존 배포 전 전체 백업 조건과 다른 승인된 순서임을 기록한다.
- PR 리뷰에서 같은 기수의 다른 반으로 승인될 수 있는 누락을 확인했다. 승인 onboarding과 실제 enrollment의 trigger로 requested_class_id 불일치를 차단한다. 기존 요청 반이 null인 행은 기존 승인 동작을 유지한다.

- 사용자가 기존 Resend API 키를 Supabase SMTP에 직접 입력·저장했다. Management API에서 host smtp.resend.com, port 465, user resend, 발신 enrollment@er-coaching.com, 이름 ER을 확인했다. 키 값은 출력하거나 보관하지 않았다. 실제 인증 이메일 수신은 아직 검증하지 않았다.
- 코치 백업 도구 실행으로 보고서 55건·첨부 2개·실패 0을 확인했다. 학생별 미연결 55건으로 purge_gate.ok=false다. 전체 교육 DB·Storage 백업·복원 완료로 취급하지 않는다.

- 2026-10-05 사용자가 모든 운영 확인 항목에 동의하고 교육 기록 1년·로컬 다운로드·동의 증거 시장 기준 적용을 승인했다. 수료 후 1년을 적용하며 로컬 복사본도 무기한 보관하지 않는다.
- 증거는 철회·탈퇴 후 5년의 최소 기록 보관을 운영 기준으로 선택한다. 질서위반행위규제법 제19조의 제척기간을 참고하지만 업계 공통 의무나 개인정보 보관의 독립적 법적 근거로 제시하지 않는다. 연락처와 교육 원문을 증거에 포함하지 않는다.
- 현재 Auth smtp_host가 null이다. Supabase 기본 SMTP는 조직 외 학생 주소를 허용하지 않으므로 실제 SMTP 연결 없이 공개 이메일 가입 완료로 보고하지 않는다.
- 기존 교육 백업 설정·Storage 키 파일에 placeholder가 남아 있다. CoachPortal의 기존 service-role 키는 sb_secret 형식이다. 실제 백업·복원 확인 전 운영 migration을 적용하지 않는다.

- PR #53은 시안과 기록 설계만 포함한다. 고객 66건에는 확인된 수신 동의가 없어 과거 동의를 만들지 않는다.
- 기존 사이트에서 운영자 에니어그램 포 레스토레이션·대표 손지영·연락처 hello@er-coaching.com을 확인했다. 교육 계정의 보관 기간과 이 정보의 적용 여부는 사용자 확인을 요청했다.
- 소셜 인증 계정과 ER 회원 등록 완료를 구분한다. 서버에 완료 상태가 저장되기 전에는 신규 계정의 수강 신청을 허용하지 않는다.
- 기존 회원은 전환 시점에 legacy 상태로 기록하며 이것을 동의의 증거로 취급하지 않는다.
- 카카오 로그인 권한·채널 친구 관계와 ER의 카카오 수신 동의를 구분한다. 이 작업은 채널 연결이나 메시지 발송을 실행하지 않는다.
- 법적 문구가 미확정이면 승인 문서가 없는 상태로 구현한다. 테스트 문서를 운영에 공개하지 않는다.
- 직접 코치 주소로 진입하는 경로에도 가입 상태 확인을 연결했다. 신규 미완료 회원의 교육·코치 RLS와 수석 권한 검증을 제한하고 기존 회원의 권한은 유지한다.
- Supabase 기본 service_role 권한이 전용 증거 테이블에 남지 않도록 명시적으로 회수했다. 발송 대상 조회 RPC와 승인 문서 등록 권한만 제공한다.
