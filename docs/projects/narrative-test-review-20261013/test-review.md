# 내러티브 테스트 리뷰와 정확도 검증

검토일: 2026-10-13, 한국 시간. 기준은 이 작업 공간의 `test.html → js/test.js` 및 `assessmentVersion: word-narrative-v2`이다. 과거 39문항 검사와 운영에서 로드하지 않는 helper는 별도로 평가했다. 아래 최종 배포 검증까지 완료했으며, 실제 운영 사이트에서도 같은 기능을 확인했다.

현재 검사에는 후보별 비교 기회를 같게 만들고, 동률·불충분한 응답을 보류하는 장치가 있다. 이번 검증에서 운영 채점의 합성 사례 1,785개가 예상대로 동작했다. 같은 세션에서 공식 Supabase 프로젝트 `osdynbadhtfgoxilgmpy`의 `public.diagnostic_experiment_sessions`를 읽기 전용 집계로 확인한 결과, 제출된 실제 기록은 0건이었다. 버전·언어별 집계 결과도 빈 배열이었다. 따라서 실제 유형 판별 정확도와 자기평가 일치도는 모두 산출할 수 없다. 개인정보나 개별 응답 원문은 조회하지 않았다.

## 1. 검사 구조와 확인된 장점

| 단계 | 실제 동작 | 판단 |
|---|---|---|
| 단어 선별 | 유형별 9개, 총 81개 단어에 예·모르겠다·아니요 응답. 예의 수로 후보 3~4개 선별 | 유형별 문항 수가 같고, 모르겠다와 미응답을 구분한다 |
| 경계 확인 | 후보 경계 동률·정보 부족이면 아홉 동기 설명에서 3~4개 후보를 직접 선택 | 유형 번호 순서로 동률을 강제 확정하지 않는다 |
| 동기 비교 | 후보의 모든 쌍에 2문항씩. 3후보는 6개, 4후보는 12개 비교 문항과 본능 3문항 | 모든 후보에 같은 비교 기회를 준다. 단어 점수는 최종 코어에 합산하지 않는다 |
| 추가 비교 | 상위 두 후보가 근접하고 세 번째보다 높으면 추가 비교 1문항 | 답이 결정적일 때만 1점을 더한다 |
| 상세 확인 | 코어가 충분히 구분되면 하위유형 3문항, 양옆 날개 3문항 | 2표 이상 우세해야 판정한다. 동률 또는 1표만 있으면 미확정으로 남긴다 |
| 결과 해석 | 코어·하위유형·날개와 후보별 근거를 함께 표시 | v2는 잠정적인 자기이해 결과이며, 점수 비율이 유형일 확률이 아님을 명시한다 |

정상적인 상세 확인 경로는 총 96문항 또는 102문항이며, 추가 비교를 거치면 각각 97문항·103문항이다. 응답이 불충분해 상세 단계로 가지 않으면 더 적다. 현재 탭의 세션 저장소는 선택값·진행 위치·검사 버전을 저장하며, 구버전 `word-narrative-v1` 기록을 v2 질문에 적용하지 않는다. 주관식 경험 기록은 새 제출에 포함하지 않는다. 서버 저장은 참가자의 동의와 명시적인 제출을 거쳐야 한다.

## 2. 수정 전 확인한 결함과 이번 처리

| 항목 | 재현 근거 | 처리 상태 |
|---|---|---|
| 영어 결과의 한국어 본문 | 영어로 진행해도 기존 `renderPremiumReport()`가 한국어 해석과 한국어 제공 안내를 출력 | 수정 완료. 모든 유형·하위유형·날개 영어 콘텐츠와 미확정 결과, 접근성 라벨 검증. 실제 브라우저 완료·복원·공유·인쇄 확인 |
| 영어 상세 문항 반복 | 9개 유형 모두 영어 하위유형 3문항의 고유 내용 수 1개, 영어 날개 3문항의 고유 내용 수 1개 | 수정 완료. 9개 유형의 하위유형·날개 각 3개 영어 문항이 서로 다른 관찰을 유지하며 한국어와 같은 선택값·채점 정의를 사용함 |
| v2 빠른 응답 감지 누락 | 기존 기준은 응답 20개 이상. 3후보 경로는 단어를 제외하면 상세 단계까지 15~16개라 기준을 넘지 못함. 15개 응답·평균 0.2초도 `level: good`, 경고 없음 | 수정 완료. v2는 최소 응답 8개, 기존 경로는 20개 유지. 15개 빠른 응답은 경고하고, 7개 이하·정상 속도·누락 타이밍은 경고하지 않는 회귀 검증 통과 |
| 분석기의 미확인 하위유형 오답 처리 | 확인 코어가 2이고 확인 하위유형은 없는데 예측 `sp_2`이면 카운터타입 오답률 1/1로 집계 | 수정 완료. 확인 하위유형 없는 행은 카운터타입 오답률 분모에서 제외 |
| 혼동쌍의 순서별 분리 | `7-9`와 `9-7`을 서로 다른 혼동쌍으로 집계 | 수정 완료. 숫자순으로 정규화해 같은 쌍으로 집계 |
| 자료가 없는데 0%로 표시 | 0/0인 지표에 `0.0%` 표시 | 수정 완료. `N/A`와 자료 없음 설명을 출력 |
| 구버전·한국어·영어 자료 혼합 | 분석기가 버전과 언어를 구분하지 않고 전체 합산 | 수정 완료. 코호트를 표시하고 `--assessment-version`, `--lang`으로 분리 가능 |

분석기 수정은 검사 채점이나 기존 서버 기록을 바꾸지 않는다. 확인된 하위유형이 있고 예측 하위유형이 미확정인 카운터타입 사례는 확인된 값과 일치하지 않은 사례로 남는다. 현재 `confirmed_type`은 참가자가 입력하는 선택값이므로, 필드 이름만으로 독립 평가자가 확인한 정답으로 취급하면 안 된다. 독립 상담 확인을 수집하려면 확인자·방법·시점을 구분하는 근거가 필요하다.

## 3. 남은 정확도 위험과 개선 우선순위

**후보 선별의 누락을 먼저 측정해야 한다.** 단어로 선별되지 않은 유형은 최종 동기 비교에서 점수를 얻을 수 없다. 후보 안에서는 단어 1위가 뒤집힐 수 있지만, 후보 밖의 실제 유형을 회복하는 자동 장치는 없다. 성격을 긍정적으로 보이게 하는 단어에 대한 동의, 부정적 단어에 대한 회피, 언어별 뉘앙스 차이가 후보 선별에 영향을 줄 가능성이 있다. 따라서 최종 일치율에 앞서 실제 확인 코어가 3~4개 후보 안에 들어온 비율을 측정해야 한다.

**선택지 위치 편향은 별도의 설계 변경으로 다룬다.** 동기 비교의 A는 항상 번호가 작은 유형이다. 후보 `[9, 4, 1]`에서 모든 비교에 A를 고르면 점수가 `1:4, 4:2, 9:0`이 된다. v2에는 리커트 직선응답 기준이 적용되지 않아 이 패턴의 `straightLineRatio`는 0이다. 한쪽 위치를 반복 선택했다는 사실만으로 오답이라고 단정할 수는 없지만, 현재 구조에서는 위치 습관과 실제 동기를 분리해 확인하기 어렵다. 문항별 좌우 균형 배치 또는 세션별 무작위화를 검토하고, 문항 ID와 선택한 실제 유형을 보존해 재현 가능하게 해야 한다. 이번 수정에서는 채점과 문항 설계를 바꾸지 않는다.

**응답 품질의 독립성을 보강한다.** v2의 센터 점수는 별도 센터 질문의 응답이 아니라 최종 유형 점수를 센터별로 합산한 값이다. 따라서 센터-코어 일치가 독립적인 정확도 검증 근거가 되지 않는다. 현재 품질 표시는 주로 빠른 응답·모르겠다 비율·본능 분명함을 설명하며, 정상 표시가 실제 정답을 보장하지 않는다. 타이밍은 전체 경과시간 평균이므로 중간 휴식이 매우 빠른 응답을 가릴 수 있다. 검증된 문항별 응답시간과 누락·반복 패턴을 추가로 수집한 뒤 기준을 조정하는 것이 좋다.

**하위유형과 날개는 코어와 분리해 검증한다.** 각 3문항의 2표 우세는 현재 코드의 판정 규칙이며, 정답일 확률이 아니다. 코어 오분류는 해당 코어의 상세 질문과 결과 해석으로 이어진다. 코어가 맞은 경우의 하위유형·날개 일치율, 미확정 비율, 전체 조합 일치율을 구분해야 한다.

**새 흐름에 구형 보정 성능을 그대로 이식하지 않는다.** 상태성 불안·카운터타입·조건부 혼동쌍 검증 중 일부는 기존 39문항 경로를 검사한다. 신규 내러티브 경로는 최근 상태 보정을 적용하지 않으며 모든 후보 쌍을 같은 수의 질문으로 비교한다. 구형 검증 통과를 v2의 상태성 불안 또는 카운터타입 판별 정확도 증명으로 사용할 수 없다.

새 운영 검증은 [narrative-accuracy-validation.test.mjs](../../../tests/narrative-accuracy-validation.test.mjs)에서 재현할 수 있다. 이 1,785개는 알고리즘의 일관성·보류 조건을 검사하는 합성 사례이며, 실제 사람의 응답으로 얻은 정확도 표본이 아니다.

`tests/simulate.mjs`는 `js/test-scoring.js`와 `js/subtypes-27-data.js`를 가져온다. 현재 `test.html`은 이 두 파일을 로드하지 않는다. 특히 `computeResult()`에 정답 코어를 직접 입력하고 본능 최고점도 미리 지정하므로, 35/35 통과는 코어를 맞추는 능력을 검사하지 않는다. 구형 helper는 본능 동률에 `sx > sp > so`를 적용하고 날개 동률에 0% 우세 날개를 반환하지만, 운영 v2의 상세 다수결은 동률을 미확정으로 남긴다. 두 검증을 같은 정확도 지표로 합치면 안 된다.

## 5. 정확도 fixture 분석

실제 제출 기록은 0건이며, 아래 수치는 실사용 자료가 아니다. 저장소의 `tests/fixtures/diagnostic-experiments.sample.json`은 분석기 회귀검증용 4행이다. 현재 검사 버전과 언어가 기록되어 있지 않아 분석기는 `unversioned / unknown`으로 표시한다. 실제 상담 자료로 검증된 표본이라는 근거가 없으므로 운영 정확도 수치로 제시하지 않는다.

이 fixture에서 코어·하위유형이 모두 일치하는 행은 2개이고, 낮은 신뢰도 행 1개와 품질 경고 행 2개는 불일치한다. 카운터타입 관련 2행 중 1행이 불일치한다. 이 값들은 분석기의 합성 입력에 대한 예상 출력 확인용이다. 모집단·표본 크기·확인자의 독립성·언어별 정확도를 설명하지 못한다. 변경 전후 재실행에서 이 fixture의 예상 혼동 결과는 유지되었고, 혼동쌍 표기만 정규화됐다.

실제 익명화 export를 분석할 때는 다음처럼 버전과 언어를 분리한다.

```sh
node scripts/analyze_diagnostic_experiments.mjs \
  --input path/to/diagnostic-experiment-export.json \
  --assessment-version word-narrative-v2 --lang ko
node scripts/analyze_diagnostic_experiments.mjs \
  --input path/to/diagnostic-experiment-export.json \
  --assessment-version word-narrative-v2 --lang en
```

## 6. 실제 검증 계획

1. 동의 받은 v2 자료를 버전·언어·확인 출처별로 분리하고, 중복 응답·미완료·확인값 누락을 별도 집계한다. 자기보고 일치도와 독립 상담 확인 일치도를 구분한다.
2. 유형별 표본 수와 후보 포함률을 먼저 보고한다. 후보 누락과 후보 내부의 오분류를 나눠 문항 선별 문제와 동기 비교 문제를 구분한다.
3. 코어 일치율, 유형별 정밀도·재현율, 혼동행렬, 미확정 비율을 함께 보고한다. 코어가 맞은 표본의 하위유형·날개 일치율과 전체 조합 일치율을 따로 산출한다.
4. 한국어·영어, 경계 동률, 모르는 응답 비율, 빠른 응답, 카운터타입에서 결과를 분리한다. 동일 참가자의 재검사 안정성도 확인한다.
5. 변경 제안은 먼저 문항 이해 문제·후보 선별·라우팅·가중치 문제로 나눈다. 기존 저장소 기준은 유효 행 최소 100개, 영향받는 혼동쌍 최소 20개와 변경 전후 replay다. 이는 가중치 변경을 위한 최소 운영 기준이며, 검증된 정확도를 보장하는 표본 설계는 아니다.
6. 실제 표본 수와 불확실성 범위를 함께 제시하고, 모델 개선에 사용하지 않은 검증 자료에서 변경의 효과를 확인한다. 자료 확보 전에는 점수 비율이나 합성 테스트 통과율을 실제 정답률로 홍보하지 않는다.

우선순위는 **영어 문항·결과 동등성 및 빠른 응답 누락 수정 → 후보 포함률과 언어별 확인 자료 수집 → 위치 편향과 문항별 응답 품질 설계 → 자료에 근거한 문항·라우팅·가중치 보정**이다.

- `node --test`로 배포 안전·현재 내러티브·영어 결과·응답 품질·상세 선택·실험 제출·분석기·기존 helper 검증 총 **145/145 통과**했다. 세부 합성 사례 1,785개는 이 테스트 안에서 검사하며 별도의 실제 사람 표본으로 합산하지 않는다.

- 관련 사이트 회귀검증 **53/53 통과** 및 소개 화면 한국어·영어 전환 검증. 사이트와 검사 변경은 각각 별도 PR로 배포한다.
- 브라우저 증거는 [browser-validation.json](browser-validation.json), 채점·데이터 검증 범위는 [diagnostic-validation.json](diagnostic-validation.json)에 기록한다.
