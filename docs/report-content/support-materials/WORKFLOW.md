# Result Support Materials Workflow

이 문서는 새로 받은 PDF 자료를 프리미엄 결과지에 조건별로 붙이는 내부 워크플로우입니다. 고객 결과지에는 원본 파일명, source note, 제작 메모를 노출하지 않습니다.

## 1. 용어

| 내부 코드 | 한국어 | 프로젝트 별칭 | 억압형 의미 | 상태 |
|---|---|---|---|---|
| `sp` | 자기보존 본능 | 자본 | 자기보존 본능이 지극히 낮은 경우 | 사용 가능 |
| `sx` | 성적/일대일 본능 | 성본 | 성적 본능이 지극히 낮은 경우 | 사용 가능 |
| `so` | 사회적 본능 | 사본 | 사회적 본능이 지극히 낮은 경우 | 사용 가능 |

억압형은 dominant subtype을 바꾸는 값이 아닙니다. 예를 들어 `sx_7_w8`인 사람도 `so`가 극히 낮으면 “사회적 본능 억압형 보조 해석”이 붙을 수 있습니다.

## 2. 판정 순서

1. 핵심 유형, 날개, dominant instinct, 27 subtype을 먼저 확정합니다.
2. 세 본능의 절대 퍼센트 값을 확인합니다. 본능 퍼센트는 합계 100이 아니라 각 본능의 독립 강도입니다.
3. 가장 낮은 본능이 `25% 이하`인지 확인합니다.
4. 가장 낮은 본능과 중간 본능의 차이가 `20포인트 이상`인지 확인합니다.
5. 가장 낮은 값이 3포인트 이내로 동률이면 억압형으로 판정하지 않습니다.
6. `so`이면 사본억압형 자료, `sx`이면 성본억압형 자료, `sp`이면 자본억압형 자료를 엽니다.

이 기준은 [catalog.json](./catalog.json)의 `thresholds.instinctSuppression`에서 조정합니다.

## 3. 자료별 사용 위치

| 자료 ID | 결과지에서 쓰는 위치 | 조건 |
|---|---|---|
| `self_preservation_instinct_repressed` | 본능 프로필, 몸/돈/시간/안전/경계, 부모 반응, 추천 자료 | `sp`가 극히 낮고 명확히 최하위 |
| `social_instinct_repressed` | 본능 프로필, 관계/팀/공동체, 부모 반응, 추천 자료 | `so`가 극히 낮고 명확히 최하위 |
| `sexual_instinct_repressed` | 본능 프로필, 일대일 관계, 갈등/표현, 부모/부부 반응, 추천 자료 | `sx`가 극히 낮고 명확히 최하위 |
| `mother_type_traits` | 부모 결과지의 양육 강점/그림자/성장 전략 | 부모용 결과지이고 성인 핵심 유형이 있음 |
| `child_observation_checklist` | 아이 유형 관찰 부록 | 아이 유형이 있거나 부모가 아이 관찰 자료를 원함 |
| `child_type_conversation_principles` | 아이 유형별 대화 원칙 | 아이 유형이 있거나 부모가 구체 대화 문장을 원함 |
| `sibling_conflict_mediation` | 형제 갈등 중재 부록 | 형제 갈등 이슈가 있거나 부모용 실전 자료 패키지 |

## 4. 고객 결과지 문장 원칙

억압형 자료는 “부족한 사람”처럼 쓰지 않습니다. 낮은 본능이 만드는 빈자리, 놓치기 쉬운 감각, 성장 연습으로 씁니다.

아이 자료는 유형 확정처럼 쓰지 않습니다. “이 아이는 N번입니다”보다 “반복 관찰되는 패턴이 N번 렌즈와 닮아 있다면”으로 씁니다.

부모 자료는 죄책감을 만들지 않습니다. “그림자”는 나쁜 점이 아니라 강점이 스트레스에서 과해진 모습으로 설명합니다.

형제 싸움 자료는 부모를 재판관으로 만들지 않습니다. “누가 먼저냐”보다 안전, 감정 번역, 경계, 회복 순서로 씁니다.

## 5. 결과지 생성 파이프라인

```text
raw test result
  -> core / wing / dominant instinct / 27 subtype 확정
  -> instinct percent rows 정규화
  -> detectRepressedInstinct()
  -> selectSupportMaterials()
  -> application layer: 필요 / 욕구 / 강점 / 방어 / 힘들 때 도움 / 타인을 도울 방법
  -> 결과지 섹션별 content brief 생성
  -> 고객용 문장으로 재작성
  -> source note / internal path 제거 QA
```

## 5-1. Application Layer 원칙

결과지는 “나는 N번입니다”에서 끝나지 않고, 실제 관계와 상담/스쿨 전환으로 자연스럽게 이어져야 합니다. 운영 결과지의 `report-application` 섹션은 다음 6개 축을 반드시 보여줍니다.

- 나의 필요
- 나의 욕구
- 강점
- 방어/약점
- 내가 힘들 때 필요한 도움
- 가족·동료·리더가 나를 도울 방법

이 섹션은 하드 세일즈 블록이 아닙니다. 사용자가 자기 이해를 얻은 뒤, 다른 사람의 필요와 약점까지 읽고 실제로 도울 언어가 필요하다는 흐름으로 상담과 스쿨 이유를 연결합니다.

## 6. QA 체크리스트

- `sourceFile`, `source note`, `ANARA`, 내부 메모가 고객 PDF에 남아 있지 않은가?
- 사본억압형을 “사람을 싫어함/사회성 부족”으로 표현하지 않았는가?
- 성본억압형을 “매력 부족/사랑 없음/연애 불능”으로 표현하지 않았는가?
- 자본억압형을 “게으름/무책임/생활관리 실패”로 표현하지 않았는가?
- 아이 유형 자료를 확정 진단처럼 말하지 않았는가?
- 부모 자료에서 죄책감보다 실천 전략이 앞에 보이는가?
- 같은 문장이나 의미가 여러 페이지에서 반복되지 않는가?
